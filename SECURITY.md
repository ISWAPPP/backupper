# Межі безпеки

Це очищений знімок наявного сервера, не результат повного security-аудиту.

- Реєстрація SSH-ключів та створення сесій публічні. UUID — bearer-посилання: хто знає його, може завантажити архів або скасувати сесію. Не використовуйте для недовірених користувачів без окремої автентифікації/мережевих обмежень.
- Відновлений сервіс видаляє незавершені incoming-сесії під час старту. Не перезапускайте його під час завантаження.
- При помилці tar наявний код також прибирає вхідні файли. Не вважайте цей сервіс єдиною копією даних; до усунення цього ризику використовуйте лише для тимчасової передачі копій.
- Архіви не видаляються після завантаження: cron видаляє їх за `find -mtime +3` (після чотирьох повних 24-годинних періодів), незавершені incoming-каталоги — за `-mtime +1`.
- Логи сесій не мають автоматичної ротації. Вони можуть містити шляхи, імена хостів та користувачів.
- Примусовий SSH-wrapper обмежує rsync-команду, але всі сесії працюють одним Unix-користувачем; це не контейнерна ізоляція.
- На вихідному сервері UFW був неактивний, SSH приймав пароль, API слухав лише 127.0.0.1:8000. Не копіюємо слабкі SSH/firewall-налаштування автоматично.
- Discord webhook зберігається лише у `/etc/backup-probe/`, поза Git, права 0600. У репозиторій не включено TLS/SSH private keys, webhook, клієнтські дані, логи або стару Git-історію.

Перед видаленням старого сервера окремо перевірте дані та інші завдання. Експорт охоплює Backup API та його інфраструктуру, не домашні каталоги, Hermes/IDE-середовища чи сторонні експерименти.
